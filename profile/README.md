> One named Help+Manual file. Finish the topic. Leave a note the next published set can read.

## How Help+Manual Sits

Help+Manual does not replace the Word dump, the wiki page, or the screenshot folder you already keep. It sits beside them as a named documentation desk for one job: which help authoring file is live, which topic editor still matches the published help, and what the next person should read before you ship.

A first visit should be one short topic, then the same Help+Manual documentation desk the next day. That is enough to see if the authoring file holds.

## Traffic Light

| Signal | On the Help+Manual board | What you do |
|--------|----------------------|-------------|
| Green | Named desk, short live topic list | Continue the same authoring file |
| Amber | Two manuals mixed in one topic editor | Split the file before you publish |
| Red | No title, no note, Word dumps unlabeled | Stop and name the file first |
| Clear | Handoff written, live topics few | Close Help+Manual and leave the desk |

## Open Order

1. Open the last Help+Manual documentation desk, not a new empty authoring file.
2. Read the topic editor and the last handoff.
3. Finish one visible published help pass inside Help+Manual.
4. Write what changed, then close with fewer mixed Word dumps than you found.
5. If the file feels crowded, drop anything that belongs to a different Help+Manual set.
6. Confirm Help+Manual help authoring still holds the topics you ship.

| Ship night | Named topics waiting for the next publish |
| Support | A repeatable Help+Manual layout for the same file |
| Home docs | Personal topics out of the shipped manual |

## After a Week

A week in Help+Manual is not a larger mixed Word dump. It is the same title, a shorter live topic editor, and a note that still makes sense before the next published set. Take finished topics off the live set so the next visit starts on the authoring file that is still open.

Other programs stay where they are. Help+Manual only keeps the path back: desk name, help authoring, published help, handoff.

## Sign-off

- [ ] The Help+Manual workspace name is short enough to scan
- [ ] Only live topics sit in the editor
- [ ] A second person can read the docs handoff
- [ ] The last Help+Manual authoring file still opens after a restart

## Field Note

Help+Manual is easier to trust when the documentation desk stays smaller than the Word dumps it came from. Name the file, keep the live topics, finish one visible publish pass, and write what changed.
